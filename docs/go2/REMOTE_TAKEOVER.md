# 官方手柄接管网页测试

当前网页：http://192.168.50.1:8765/ 。点击“实际测试 / 手柄接管…”，默认选择“手柄接管 · 0.30 m/s”。该模式固定前方2m、侧向0、指令上限0.30m/s，默认8秒，可选4–8秒。原0.5m目标会过早结束，所以此模式单独延长目标，不改变普通导航/3秒速度标定的限制。

## 操作

1. 官方手柄开机连狗，保持可接管；前方至少4m平整空旷。网页先不启动，狗由现场人员正常站立。
2. 在确认空旷的情况下，通过日常手柄操作核对弹窗“摇杆/按键”读数实际变化，然后归中、松开按键至少0.5秒。此阶段网页不发运动指令，手柄本身仍可让狗动作。请勿为了验证乱按组合键。
3. 到参数页完成本次静态地面复核，再回弹窗。两分钟内须检测到实际手柄操作；未收到数据、未归中、未观察到操作、地面过期或未勾确认时按钮禁用。需要时在空旷处重新核对输入。
4. 核对弹窗的2m/0.30m/s/时限和现场条件，再手动点“启动本次实际试验”。不会自动站起、改步态或切厂家运控模式。
5. 轻推任意摇杆超过约20%并回中，或使用已熟悉的单独按键：程序锁存退出，页面应显示“手柄触发接管，程序已退出”。确认退出后再按日常方式遥控，不会松开摇杆就恢复导航。

到点、障碍、输入过期、页面心跳中断、桥端8秒/2m上限也会提前结束；这是时限上限，不保证持续走满8秒。窗口切后台/切页面会停止心跳。接管功能已完成下述单轮现场验收；精确物理停止延迟/距离仍须专门测量。

## 实现与边界

- 手柄通过本体遥控链路起作用，不需SSH运动控制主机。盒子只订阅本体DDS。
- 官方SDK的独立rt/wirelesscontroller示例通道在本机没有实际消息；只读探测3秒，processed/unprocessed均0，rt/lowstate约1495包。改用官方state_machine/gamepad.hpp给出的wireless_remote 40字节布局（keys偏移2，lx/rx/ry/ly偏移4/8/12/20）。本机观察到头0x55/0x51，头或轴值非法即拒绝。
- Native RemoteTakeover要求连续中位0.5秒；启动后按钮/轴超阈值会锁存，归中不解除。500ms没收到有效数据通道也锁存；Python故障时仍由独立C++循环执行。结束SDK输出并调用StopMove，不发送模式选择或底层电机命令。
- LowState持续发布可能包含缓存的无线数据；“数据新鲜”不能证明物理无线链路在线，不能把手柄断电等同于一定500ms内被检测。手柄须现场保持开机连接，2分钟内的真实输入验证及独立时限/停止按钮仍有必要。
- read_state识别bridge_event并终止本轮；后台恢复只读状态桥，不恢复执行桥。日志保存takeover_test/remote信息及结束原因。
